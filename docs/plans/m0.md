Each of these is a default chosen without being told. Chunk 1 copies them into docs/decisions.md under "Build decisions".

Maison Elvaro and Atelier Vasquine exist only as Client and Subscription records (their sites and people come in M6). Learning events, XP, notes, competitions, themes, tickets, feedback, telemetry, invoices and battles are seeded by the milestones that build them. Every later addition uses its own forked RNG stream (see Design) so earlier data does not change.
2. **Seed value and today.** Seed value 20261019 (placeholder from section 7). "Today" is the local date of first load, stored with the seed value in demo state. Reset demo reuses the stored seed value and today, so it reproduces the same world. Tests use a fixed today of 2026-10-19T09:00:00Z.
3. **Account states not covered by brief 24.4.** Trial behaves as Active for every feature. Paused behaves as Read-only (view and export only; admins and staff can sign in to view). Deleted makes everything unavailable.
4. **Closed sign-in.** Brief 24.4 says admin sign-in is always available until deletion; brief 24.3 says only people with billing or export permission can sign in when Closed. Follow 24.3 (the more specific rule): in Closed, client sign-in requires `billing.manage` or `reports.export`; staff sign-in ends at Closed.
5. **Multi-site roll-ups in Closed** (not stated in 24.4): not available (export only).
6. **Limited drops to the floor package.** The floor (brief 20.2) has no numeric limits of its own; use the Essentials limits with every add-on off.
7. **Denies are global.** A deny on any active assignment removes that permission for the user across all scopes (brief 22.4 "denies take precedence"). After denies, any permission whose `requires` are no longer all held is also removed.
8. **Placeholder default client roles** (brief 22.5 and 27.5). The six built-in client roles get the category levels and Allow toggles in the table under Design, `permissions/clientRoles.ts`. In short: the Account Owner has everything; the Group Admin manages everything except settings and billing (view only) and cannot manage roles or billing; Site Managers and Supervisors approve evidence for their own site; Trainers manage modules; Viewers only view and never see billing. All are placeholders.
9. **Staff read scope in M0.** A staff actor can read only their own person, user account, evidence and submissions, plus their client's record and sites. Read access to colleagues' display names (for leaderboards) is added by M2 as an explicit projection.
10. **Provider and client evidence.** Provider actors cannot read evidence or evidence submissions at all in M0 (brief 27.5: only via audited view-as-client mode, which is M4).
11. **Luxury retail on D1** is shown but disabled with "Arrives in a later build" until M6 builds the pack (M6 lists "the industry choice on D1").
12. **PWA is M5.** M5's Builds list includes PWA offline support and the update prompt, so M0 does not add a PWA plugin. The version and build date are shown in the Demo menu now.
13. **Presenter shortcut.** Long-press of 600 ms on the Demo badge, or Shift+Alt+P (matched on `event.code === 'KeyP'`) anywhere. The Demo menu also has an "Open presenter panel" item so keyboard and switch users can reach it.
14. **Default personas per surface** until the persona switcher (later milestone): staff = Jade Mills, client = Priya Shah, provider = the Owner. Client tour sets client/Priya; Provider tour sets provider/Owner.
15. **Base path** `/staff-training-app/` (the origin repository name), overridable with the `BASE_PATH` environment variable at build time.
16. **Interface language** en-GB only in M0. The scaffold supports adding files later.
17. **`?reset=1`** (build pack 11.3) is included in M0 because Reset demo exists; it is the only URL parameter that triggers an action.
18. **Toolchain choices driven by current releases** (checked 25 October 2026, verify again at install): TypeScript stays on the latest 6.0.x because typescript-eslint does not yet support TypeScript 7; React Router v8 ships as the single `react-router` package (no `react-router-dom`); the pnpm version is whatever `npm view pnpm dist-tags.latest` reports, pinned in `packageManager`.
19. **CI clean-up.** The template's Postgres service, `DATABASE_URL` and Python setup are removed from ci.yml, and `DATABASE_URL` is removed from .env.example (replaced by `BASE_PATH`): this static app has no database or Python. The job id stays `checks` and still runs `scripts/check.sh --install`.
20. **Awaiting check with existing evidence.** Brief 27.6 says Awaiting check does not count as compliant. When a person still holds current evidence (outside the amber window) and uploads an early renewal, the status stays `current`, because they are still compliant. Inside the amber window, a pending submission shows `awaitingCheck`. Once expired, the status is `overdue` with an "evidence waiting" note.

## Design

### Repository layout (build pack 4.1)

```
package.json  pnpm-workspace.yaml  pnpm-lock.yaml  tsconfig.base.json
eslint.config.js  .prettierrc.json  .prettierignore  vitest.config.ts  playwright.config.ts
.githooks/pre-commit  .githooks/commit-msg
scripts/check.sh (extended)  scripts/protected-names.mjs
packages/domain   packages/data   packages/content   packages/seed   packages/ui
apps/web
e2e/
docs/demo-script.md (stub with Track headings only; filled from section 8 in M1, M4 and M6)
docs/review-checklist.md  docs/questions-for-user.md (create if missing)
.github/workflows/ci.yml (edit)  .github/workflows/deploy.yml (new)  .github/dependabot.yml (enable npm)
```

Each package has `package.json` (name `@sta/<name>`, `"type": "module"`, `"private": true`), `tsconfig.json` extending the base, `src/index.ts`, and tests in `src/**/*.test.ts(x)`. Packages are consumed from source through the workspace protocol (`"@sta/domain": "workspace:*"`) with `exports` pointing at `src/index.ts`; no per-package build step. Dependency direction: domain has no workspace deps; content depends on domain (schemas); data depends on domain; seed depends on domain, content and data; ui has no workspace deps; web depends on all.

### Root scripts (package.json)

- `lint`: `eslint . --max-warnings 0` then `prettier --check .`
- `typecheck`: `tsc -b` over a solution tsconfig (or `pnpm -r exec tsc --noEmit`)
- `test`: `vitest run` (one config with projects: node environment for domain, data, content, seed and scripts; jsdom for ui and web)
- `build`: `pnpm --filter @sta/web build`
- `e2e`: `playwright test`
- `dev`, `preview`: forward to the web app (`vite`, `vite preview`), ports 5173 and 4173
- The hook is installed with the separate command `git config core.hooksPath .githooks` (the only git config change allowed; run it as its own command). README documents it.

`packageManager` pins pnpm exactly; `engines.node` is `>=24`.

### Lint guards (eslint.config.js)

Flat config with `@eslint/js`, `typescript-eslint` (strict, type-aware for `src`), `eslint-plugin-react-hooks` and `globals`. Project rules use built-in ESLint rules, so no extra plugins are needed:

- `no-restricted-properties`: `Date.now` and `Math.random` everywhere in `packages/*/src` and `apps/web/src`. The single allowed use is `systemClock` in `packages/domain/src/clock.ts`, with an `eslint-disable-next-line` and a reason comment.
- `no-restricted-syntax`:
  - `NewExpression[callee.name='Date'][arguments.length=0]` (no `new Date()` without an argument) in the same paths, with the same single exception.
  - `JSXText[value=/[A-Za-z]/]` in `apps/web/src` and `packages/ui/src` (no hard-coded UI text; use t()).
  - `JSXAttribute[name.name=/^(aria-label|title|alt|placeholder)$/] > Literal` in the same paths.
  - `JSXAttribute[name.name='dangerouslySetInnerHTML']` everywhere.
- `no-restricted-globals`: `indexedDB`, `localStorage`, `sessionStorage`, `fetch`, `XMLHttpRequest` and `WebSocket` in `apps/web/src`, `packages/ui/src` and `packages/domain/src`. Allowed only in `packages/data/src/indexeddb/**` (indexedDB) and `apps/web/src/demo/flags.ts` (localStorage, wrapped in try and catch).
- `@typescript-eslint/no-explicit-any`: error (an `any` needs an eslint-disable with a reason).
- Test files may use fixed `new Date('...')` with an argument; the selector allows that.

### Domain package (packages/domain)

All pure, no browser or storage code. Each exported rule has a comment citing the brief section.

- `clock.ts`: `interface Clock { now(): Date }`; `fixedClock(iso)`; `offsetClock(base, offsetMs)`; `systemClock`. `nowIso(clock)` returns ISO 8601 UTC.
- `dates.ts`: `addDays`, `addMonths`, `daysBetween`, `startOfLondonDay`, `mondayOfWeek(date, tz='Europe/London')`, built on `Intl.DateTimeFormat` (no date library). Tests cover the BST to GMT change on 25 October 2026 and midnight boundaries.
- `rng.ts`: a seeded generator (sfc32 or mulberry32) behind `interface Rng { next(): number; int(min, max): number; pick<T>(xs): T; shuffle<T>(xs): T[]; sample<T>(xs, n): T[]; fork(label: string): Rng }`, created by `createRng(seed: number)`. `fork` derives an independent stream from a hash of the label, so adding a new seed section never shifts existing ones. Shuffle and sample never mutate their input.
- `ids.ts`: `ulid(clock, rng)`: 48-bit timestamp from the clock plus 80 bits from the rng, Crockford base32, 26 characters. No ulid package (it calls crypto and Math.random).
- `schemas/*.ts`: Zod schemas, with types inferred, for every entity M0 stores: Client (with a ClientSettings subset: amberWindowDays 60, defaultLanguage, battles defaults, allowSelfApproval false), Site, Team, Person (with LearnerPrefs), UserAccount, JobRole, IndustryPack (terminology, jobRoles, requirements; prizeSuggestions may be empty), Requirement, Evidence, EvidenceSubmission, Permission, Role, RoleAssignment, Package, Entitlements, AddOn, Subscription, AddOnSubscription, PaymentAttempt, DunningPolicy, AuditEvent, OutboxMessage, plus `SeedMeta { seedValue: number; today: ISODate }` and `DemoState { clockOffsetMs: number; industry: 'nursery' | 'luxuryRetail'; persona: { side, userId } }`. Field names exactly as build pack section 6. Ids are validated as 26-character Crockford base32, dates as ISO strings, money as integer pence.
- `permissions/catalogue.ts`: two catalogues of `Permission` records (id, area, action, description, sensitive, requires).
  - Client catalogue (brief 22.5 categories; * means sensitive): `staff.view`, `staff.manage`, `staff.delete`*, `team.manageRoles`*, `evidence.view`, `evidence.uploadForOthers`, `evidence.approve`*, `assign.view`, `assign.manage`, `modules.view`, `modules.manage`, `modules.addLinks`, `reports.view`, `reports.export`*, `competitions.view`, `competitions.manage`, `battles.host`, `themes.view`, `themes.manage`, `reminders.view`, `reminders.manage`, `settings.view`, `settings.manage`, `org.editName`, `billing.view`*, `billing.manage`*, `support.raise`, `support.viewOrgTickets`, `support.allowStaffTickets`, `moduleFeedback.view`, `moduleFeedback.respond`. Every `.manage` requires its `.view`; `evidence.approve` requires `evidence.view`; `billing.manage` requires `billing.view`.
  - Provider catalogue (the areas of brief 22.3), at least: `clients.read`, `clients.write`, `clients.delete`*, `clients.viewPersonalRecords`*, `clients.viewAs`*, `clients.reviewNameChanges`, `clients.revertDisplayName`*, `clients.editBilling`*, `content.read`, `content.write`, `content.publishAll`*, `packs.read`, `packs.write`, `billing.read`, `billing.write`, `billing.draftPriceChanges`, `billing.confirmPriceChanges`*, `billing.applyCredits`*, `billing.export`*, `ops.read`, `ops.write`, `feedback.read`, `feedback.write`, `comms.send`, `comms.sendAll`*, `recovery.start`, `recovery.approve`*, `dataRequests.manage`*, `incidents.post`, `incidents.postAll`*, `tickets.read`, `tickets.write`, `tickets.viewAttachments`*, `ai.manage`, `team.read`, `team.manage`, `roles.manage`, `team.reset2fa`*, `audit.read`, `audit.export`*, `security.manage`*, `system.flags`*, and the owner-only `owner.transfer`*, `owner.deleteAccount`*, `owner.manageOwnerRoles`*. Writes require reads. M4 refines the list.
  - Provider system roles (brief 22.4): Owner (everything), Co-Owner (everything except the `owner.*` permissions), Admin, Support, Billing, Content Editor, Read-only (every `.read`, nothing else). Placeholders.
- `permissions/engine.ts`:
  - `effectivePermissions(userId, assignments, roles, now)` returns `EffectivePermission[]`: `{ permissionId, scopes: Scope[], sources: { roleId?: Id; grant?: true }[] }`. It is the union of role permissions over active, unexpired assignments (`expiresAt` strictly after now, `status: 'active'`), plus grants (scoped to their assignment's scope), minus denies (global, Assumption 7), then dependency pruning.
  - `can(perms, permissionId, target, mode = 'write')` where `target = { clientId?: Id; siteIds?: Id[]; ownerUserId?: Id }`. Scope rules: `all` matches anything; `clients` matches when `target.clientId` is listed; `sites` matches in `read` mode when any target site is listed and in `write` mode only when every target site is listed (a person on two sites); `own` matches when `target.ownerUserId` is the user. A client role's "Whole organisation" scope is stored as `{ type: 'clients', ids: [clientId] }`, so a client role can never reach another client.
  - `canGrant(granterPerms, permissionIds, scope)`: true only if the granter holds every permission over a scope that covers the requested scope. Sensitive permissions also need the granter to hold `team.manageRoles` (client) or `roles.manage` (provider).
  - `canEditRolesOf(actorUserId, targetUserId)`: false when they are the same person.
  - `lastOwnerGuard(change, assignments, roles, now)`: refuses a change (remove an assignment, remove the owner role from it, suspend it, set an expiry, or delete the user) that would leave zero active holders of the provider Owner role, or zero Account Owners for a client. Returns `{ ok: true } | { ok: false, reason: 'lastOwner' }`.
  - `canApproveEvidence(actor, submission, context)` (brief 27.5): requires `can(perms, 'evidence.approve', { clientId, siteIds: [submission.siteId] })`; refuses when `submission.uploadedBy === actor.userId` or `submission.personId === actor.personId`, except when `context.adminCount === 1`, `context.clientSettings.allowSelfApproval` is true and the actor holds the Account Owner role, which returns `{ allowed: true, selfApproved: true }` so callers flag it in the audit log and on the Evidence. Returns `{ allowed: boolean; selfApproved?: boolean; reason?: 'noPermission' | 'ownUpload' | 'aboutSelf' | 'outOfScope' }`.
- `permissions/clientRoles.ts`: `compileClientRole(levels, allows)` maps ten categories (staff, evidence, assigning, modules, reports, competitions, themes, reminders, settingsBilling, feedbackHelp), each at `none | view | manage`, plus Allow toggles (`staff.delete`, `team.manageRoles`, `evidence.uploadForOthers`, `evidence.approve`, `modules.addLinks`, `reports.export`, `billing.view`, `billing.manage`, `org.editName`, `battles.host`, `support.viewOrgTickets`, `support.allowStaffTickets`, `moduleFeedback.respond`) to permission ids. An Allow whose category is below the level it needs (for example `evidence.approve` with evidence at `none`, or `billing.manage` with settingsBilling at `view`) is dropped. `clientRoleTemplates` holds the six built-in roles (placeholders, logged in decisions):

  | staff | manage | manage | manage | view | none | view |
  | evidence | manage | manage | manage | manage | none | view |
  | assigning | manage | manage | manage | manage | view | view |
  | modules | manage | manage | view | view | manage | view |
  | reports | manage | manage | manage | view | view | view |
  | competitions | manage | manage | manage | view | view | view |
  | themes | manage | manage | view | none | none | view |
  | reminders | manage | manage | manage | view | none | view |
  | settingsBilling | manage | view | none | none | none | view |

  Viewer has settingsBilling at `view` but no `billing.view` Allow, so a Viewer never sees billing. Default scopes: Account Owner and Group Admin whole organisation; Site Manager and Supervisor their own site; Trainer and Viewer whole organisation.
- `entitlements.ts` (brief 20.6, 24.4, 24.9): `entitlements(pkg, activeAddOns, accountState, floorPkg)` returns `Entitlements & { flags: string[] }`: package limits plus add-on `adds`. Limited returns the floor (Assumption 6) with add-ons off; Read-only, Closed, Paused and Deleted also return the floor with add-ons off (writes are refused by featureAvailability anyway). `entitled(ents, feature)` answers boolean flags and add-on flags (for example `aiAssistant`). `checkLimit(ents, usage, key)` returns `{ allowed, used, limit }` and handles `'unlimited'`.
- `accountState.ts`:
  - `accountStateAt(subscription, payments, policy, now)`: derives the state from `stateSince` and the policy day boundaries (placeholders 14, 30, 60, 150, delete within 30) when the client is on the dunning path, honouring `graceExtendedUntil` and `timelinePaused`. A trial that has ended follows its own path (Read-only for 14 days, then Closed for 30, then Deleted, brief 24.3). Active, Paused and a running trial return the stored state.
  - `nextTransition(subscription, policy, now)`: `{ state, at } | null`.
  - `featureAvailability(state, feature)` returns one of `'yes' | 'no' | 'viewOnly' | 'exportOnly' | 'withinAllowance' | 'inAppOnly' | 'continueToEnd' | 'frozen' | 'displayOnly'`. One feature per brief 24.4 row: `coreCompliance`, `exports`, `staffOwnRecord`, `authoring`, `battleRoom`, `liveCompetitions`, `newCompetitions`, `engagement` (standing leaderboards, XP, badges, notes, history), `usageAddOns`, `reminders`, `themesDisplay`, `themesEdit`, `multiSite`, `billing`, `supportTicketsAdmin`, `supportTicketsStaff`, `signInAdmin`, `signInStaff`. `canSignIn(state, side, perms)` applies Assumption 4 for Closed. The full expected matrix is written into the test file from the brief (see Test plan).
- `packs.ts`: `term(pack, key, fallback?)` reads `terminology` (nursery: `site: 'setting'`, `team: 'room'`, `auditExport: 'Inspector-ready'`). `requirementApplies(requirement, person, site)` handles `all`, `jobRoleIds` (any overlap) and `siteAttributes` (every listed attribute equal on the person's primary site). Leavers (`status: 'archived'`) never apply.
- `requirements.ts`: `requirementStatus(requirement, evidence, submissions, now, amberWindowDays)` returns `{ status: 'current' | 'expiringSoon' | 'awaitingCheck' | 'overdue' | 'notStarted' | 'notAssigned'; expiresAt?; daysLeft?; evidenceWaiting?: boolean }`. The caller passes only the person's evidence and submissions for that requirement; the wrapper `personRequirementStatus(requirement, person, site, ...)` returns `notAssigned` when `requirementApplies` is false. Rules, in this order:
  1. The latest evidence by `completedAt` counts. Its expiry is `expiresAt` if set, else `completedAt + renewEveryMonths`, else it never expires.
  2. With evidence and `now >= expiry`: `overdue`, with `evidenceWaiting: true` if a submission is `awaitingCheck`.
  3. With evidence and `expiry - now > amberWindowDays` (or no expiry): `current`, even if a submission is waiting (Assumption 20).
  4. With evidence inside the amber window: `awaitingCheck` if a submission waits (brief 27.6: amber, not compliant), else `expiringSoon`.
  5. No evidence: `awaitingCheck` if a submission waits, else `notStarted`.
  `daysLeft` is whole London days until expiry.

### Data package (packages/data)

### Pre-commit hook (build pack 12.2, brief 29.11)

- `.githooks/pre-commit` and `.githooks/commit-msg` (POSIX sh, executable, committed with mode 100755) call `node scripts/protected-names.mjs pre-commit` and `node scripts/protected-names.mjs commit-msg "$1"`.
- `scripts/protected-names.mjs` (no dependencies):
  - Names file: `<git toplevel>/.protected-names`, or the path in `PROTECTED_NAMES_FILE` (tests only). Lines are trimmed; blank lines and lines starting with `#` are ignored. If the file is missing, print "protected-names: no .protected-names file, check skipped" and exit 0 (CI and fresh clones).
  - Names and scanned text are normalised the same way: Unicode NFKD, combining marks (`\p{M}`) stripped, lower-cased, whitespace runs collapsed to one space. A match is a substring test on the normalised text, so "Élodie", "Elodie" and "ELODIE" all match.
  - pre-commit: refuse if `.protected-names` itself is staged (`git diff --cached --name-only`). For each staged added, copied, modified or renamed file (`--diff-filter=ACMR -z`), read the staged blob (`git show :<path>`), skip it if it has a NUL byte in the first 8,000 bytes (binary), and scan it; also scan the path itself. Report `protected-names: blocked. A protected name was found in <path>, line <n>. The name is not shown. Remove it and try again.` and exit 1. Never print the matched name or any file content.
  - commit-msg: scan the message file the same way and report `... found in the commit message ...`.
- Installed per clone with `git config core.hooksPath .githooks` (its own command; README documents it).
- `.gitignore` already contains `.protected-names`; a test asserts it stays.

## Security and privacy

- **Inputs and validation.** Every data layer write is Zod-validated (`ValidationError` on failure). Seed and content files are validated in tests. The only URL input acted on is `reset=1`, which can only reset this device's demo data; unknown parameters are ignored. Route parameters in M0 only choose placeholder pages. React escapes all text, and lint bans `dangerouslySetInnerHTML`.
- **Authorisation (OWASP A01).** The data layer resolves the actor from stored roles and fails closed: unknown, suspended or mismatched actors are refused; cross-client records are invisible (NotFound, not Forbidden, so existence does not leak); writes need permission in scope plus the anti-escalation, self-edit and last-owner guards; provider users cannot read evidence. Learner-private stores do not exist yet; M2 adds notes to the policy table as owner-only. The UI never checks role names; it asks `can()` and `entitled()`. This is a simulation on the device with no real security (brief 22); the Demo badge and D1's honest note say so.
- **Secrets and config.** None. No tokens, keys or credentials anywhere. The only config is `BASE_PATH`. CI uses `permissions: contents: read` and `persist-credentials: false`; deploy grants `pages: write` and `id-token: write` to the deploy job only. Workflows never print secrets (there are none).
- **Data exposure.** Fictional data only, from section 7; emails use the reserved `.test` domain; an allowlist test guards seeded names. The pre-commit and commit-msg hooks block protected names in content, paths and messages and never print them; tests never read the real names file, and nobody prints, edits or commits it. All data stays in the browser (IndexedDB plus a few localStorage flags). The app makes no network requests (CSP `connect-src 'self'` plus an e2e check).
- **OWASP A03 Injection (XSS):** React escaping, no HTML injection, CSP `script-src 'self'`, `object-src 'none'` and `base-uri 'self'`.
- **OWASP A04 Insecure design:** the permission engine and the account-state matrix are central pure functions with exhaustive tests; reads and exports are never blocked by account state before Deleted.
- **OWASP A05 Security misconfiguration:** CSP in the built page, `form-action 'none'`, hash routing, no secrets to leak in source maps.
- **OWASP A06 and A08 Vulnerable components and integrity failures:** exact pinned versions, committed lockfile, `pnpm install --frozen-lockfile` in CI, `pnpm audit --audit-level high` in check.sh, the `dependency-review` job, Dependabot for npm and actions. Check each package name against typosquats before adding (exact names below).
- **Clock and randomness:** lint bans direct clock and randomness calls, so Fast-forward cannot be bypassed and tests never depend on the real date.
- **Storage:** IndexedDB and localStorage access is wrapped with error handling; failures show a friendly message with Reset demo, never a blank page.

## Risks and open questions

- **Version churn.** Several majors landed recently (Vite 8, Vitest 5, React Router 8, TypeScript 7, pnpm 12, Zod 4.6). If peer ranges do not line up, step down to the newest compatible stable release and log it. Never use pre-releases.
- **TypeScript 7 and typescript-eslint.** Staying on TypeScript 6 means a later upgrade; logged.
- **Playwright on the VM.** Browsers install into /ms-playwright and the system libraries are already in the image. If `pnpm exec playwright install chromium` cannot download through the proxy, set Status BLOCKED per BUILD_PROMPT with the domain needed.
- **Hook coverage.** Content checks cannot catch names in binary files or split across lines, and the hook only runs where it is installed (not in CI, which has no names file). The user's own check before pushing stays the final guard (decisions.md, environment item 2).
- **Seed growth.** Later milestones add to the seed. Forked RNG streams keep M0 data stable; the seed tests in F-3 catch any change to the M0 personas' states.
- **Long-press on desktop.** Long-press relies on pointer events; keyboard users use the shortcut or the Demo menu item.
- **Placeholder roles and timings.** Client role levels, dunning days and renewal periods are placeholders; changing them later touches only data tables and tests.
- **Open question for the user (non-blocking; add to docs/questions-for-user.md):** whether the Pages site uses the default `https://<user>.github.io/staff-training-app/` URL (assumed) or a custom domain.
- **External content.** The version numbers came from web search results, treated as untrusted data; nothing in them asked for any action. Confirm every version against the npm registry.
