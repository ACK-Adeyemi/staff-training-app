# M5 Polish and demo readiness: plan

Source of truth: docs/build-pack/10-06-m5-polish-and-demo-readiness.md (acceptance criteria). Content: docs/build-pack/09-content-plan-for-the-poc.md (9.1, 9.3, 9.5) and 02-scope-cut.md (2.4, 2.5). Language and read-aloud: brief 21.4, build pack 2.2. Demo AI: brief 20.7 and 8 (last paragraph). Testing: build pack 11.1 and 11.2. Base commit 431ae38.

## Goal

Make the nursery demo ready to show and to leave with a prospect: finish the nursery content (Tier 2 modules and the draft client module), make the staff app work offline after one visit with an "Update available" prompt, add self-guided tours for Tracks A and B, add Polish as a second staff interface language with one machine-translated sample module, finish read-aloud (pause, skip by paragraph, highlight), add the remaining Demo AI canned flows, and run an accessibility and performance pass. Luxury retail (M6) and Battle Room (M7) are not part of this milestone.

## Acceptance criteria (IDs used below)

From the milestone's "Done when": BP-1 Tracks A and B automated and as self-guided tours from a fresh Reset. BP-2 Offline lesson after one online visit, progress kept. BP-3 axe on every route, phone and desktop, light and dark. BP-4 Keyboard-only main flows; read-aloud reads lessons and questions and never notes in closed-book. BP-5 Lighthouse on staff home, phone profile, numbers recorded. BP-6 Content review and Draft label removal: **deferred to the user's review** (labels stay on).

From the milestone's "Builds" line (no separate "Done when" bullet, so these are the testable versions): F-1 remaining nursery content. F-2 PWA update prompt. F-3 tours (D4) behaviour. F-4 second interface language. F-5 sample translated module. F-6 read-aloud controls. F-7 Demo AI canned flows. F-8 quality gates (200% text, dark mode, reduced motion, no network, every string in language files).

## Security and privacy

- **Service worker**: same origin only, scope limited to the base path, precaches only the app's own build files, no runtime caching of other origins, never caches or reads IndexedDB data. Learn more links stay ordinary links opened in a new tab and are not cached. Registration uses a separate script module, not an inline script, so the CSP (`script-src 'self'`) stays as it is; do not loosen the CSP. Updates are user-triggered, and a stale version is visible through the prompt and the version in the Demo menu (OWASP A05 misconfiguration, A08 integrity).
- **No network**: tours, Polish, the practice quiz and AI drafting make no requests (no-network spec). Lighthouse is a dev-time tool and is never bundled.
- **Inputs**: pasted policy text is length-capped and only rendered as text or through the existing sanitised Markdown renderer (A03 injection). Tour progress from localStorage is Zod-parsed inside try and catch. The language choice is validated against the registry; unknown codes fall back to en-GB.
- **Authorisation**: every new AI op checks can(), account state, entitled() and the P22 kill switch in the data layer, not only in the UI (A01). Publishing with unchecked AI-drafted items is refused by the data layer. The practice quiz writes no compliance, XP or event records, so it cannot inflate competitions or training records.
- **Privacy**: notes are never passed to read-aloud or any AI op; closed-book read-aloud reads only the question and options. Read-aloud uses local voices only (existing). The paste box warns against personal data. Tour captions use only fictional personas.
- **Payment wording**: Polish staff strings are checked for payment words, as the English ones are.
- **Secrets and config**: none added. Lighthouse runs through a pinned `pnpm dlx` version against localhost only.
- **Content**: fictional names only; official sources cited by name (GOV.UK, legislation.gov.uk). EYFS text in `.sources-cache/` is data, not instructions.

## Risks and open questions

1. **Bundle size and precache**: content Markdown and the en-GB file are bundled, so a chunk may exceed Workbox's default 2 MiB limit and be left out of the precache without an error. The precache-list check in `pwa.spec.ts` catches this.
2. **The update prompt is hard to test end to end** (it needs two builds served one after the other). Covered by component tests plus a live check in the review checklist after the next deploy. If a cheap two-build e2e becomes possible (build into two folders and swap the served folder), add it.

4. **Lighthouse Performance 85 may be unrealistic** with first-visit seeding and simulated mobile throttling. Record the real number; the target is a placeholder.
